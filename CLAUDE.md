## What this application does

Vaulting competition management system for Swedish equestrian vaulting ("voltige"). Manages competition start lists, scorecards, and result documents. Primary data exchange format is Excel — the app both imports Excel templates and generates Excel/PDF output for competitions.

## Build and run

Open `VoltigeClosedXML.sln` in Visual Studio. The solution has two projects:

- **WebApplication1** — ASP.NET MVC 5 / .NET Framework 4.6.2 (active, working)
- **VoltigeCore** — ASP.NET Core / .NET 10.0 (in-progress migration, not production-ready)

Build via Visual Studio or:
```
msbuild VoltigeClosedXML.sln /p:Configuration=Debug
```

Run with IIS Express (port 28813) via Visual Studio F5. There is no test suite — validation is done by inspecting generated Excel files in `output/` against samples in `Test_Voligemallar/`.

## Configuration

**WebApplication1/Web.config** — active configuration:
- `ContestId` app setting selects which contest is loaded on startup (currently 2)
- `TraHastTavling` toggles "trähästtävling" (training horse competition) mode
- `HorsePointTraHastTavling` — fixed horse score used in that mode
- Connection string points to `localhost\SQLEXPRESS`, database `WebApplication1.Classes.VaultingContextProtokoll2019`

**VoltigeCore/appsettings.json** — Core project configuration:
- `BasePath` must be set to the root of the repository (e.g. `C:\episerver\voltige\VoltigeClosedXML\`)
- `AppConfig.cs` derives `ContentRootPath`, `StartlistOutputPath`, and `OutputPath` from `BasePath`

## Architecture

### Layer structure (WebApplication1)

```
Controllers/          — MVC controllers; HomeController is the main entry point
Business/Logic/
  Contest/            — ContestService: loads and caches competition data
  Excel/              — ExcelBaseService + specialized subservices (Result, Team, Individual, StartList)
  Import/             — ExcelImportService + ExcelImportRepository: reads incoming Excel templates
  Result/             — ResultService: processes judging scores
  Pdf/                — pdfbatfileService: generates .bat scripts for PDF printing
  StartListClasses/   — StartListClassService
Classes/              — VaultingContext (EF DbContext), ScoreSheetIndividual
Models/               — EF domain entities
Migrations/           — 40+ EF migrations from 2017–2023
```

### Domain model

The core entities and their relationships:
- **Contest** → has many **StartListClass** (one competition class per start list entry)
- **StartListClass** → has many **StartListClassStep** (rounds/sessions within a class)
- **HorseOrder** — a start list slot: one Horse + Lunger + either a **Vaulter** (individual) or a **Team**
- **VaulterOrder** — positions individual vaulters within a team's HorseOrder
- **ScoreSheet** — judging scores attached to a HorseOrder/Step combination

### Data flows

**Import:** Excel file → `ExcelImportService` → HorseOrder/Vaulter/Team objects → SQL Server via EF6

**Export:** SQL Server → `ContestService` (cached) → Excel service layer (ClosedXML) → `output/` directory

**PDF:** Excel output → `.bat` batch script generated by `pdfbatfileService` → run manually to produce PDFs

### Key design notes

- `ContestService` uses static fields to cache the active contest's data in memory — reload the app to pick up database changes.
- The application is mid-migration from Framework 4.6.2 to .NET Core 10.0. The `VoltigeCore` project shares models and services incrementally. Do not assume parity between the two projects.
- AutoMapper is initialized in `Global.asax.cs` with mappings for `Contest` and `Horse`. Add new mappings there.
- EF migrations live only in the Framework project. Schema changes must be applied via `Update-Database` in Package Manager Console targeting `WebApplication1`.
